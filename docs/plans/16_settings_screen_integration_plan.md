# 16. '설정' 화면 기능 구현 및 가짜 데이터 삭제 연동 계획서

## 1. 개요 및 목적
- **목적**: '설정' 화면(`pages/settings.jsx`)의 하드코딩된 가짜 부서 데이터(`DEFAULT_DEPARTMENTS` 5개)를 완전히 제거하고, 순수하게 사용자가 등록/관리하는 실제 부서 데이터로 동작하도록 기능을 완성합니다.
- **연동 대상**:
  - '촬영' 화면(`pages/index.jsx`): 설정에서 지정된 '기본 부서'를 자동 연동.
  - '기록' 화면(`pages/records.jsx`): 설정에서 등록된 실제 부서 목록을 실시간 드롭다운으로 연동.
- **핵심 원칙**:
  - 기존 화면 모양 및 컴포넌트 구조 100% 유지.
  - 가짜 더미 데이터(생산1팀 등 5개) 자동 주입 로직 제거 (초기 빈 상태 0건 지원).
  - 브라우저 기본 팝업(`alert`, `confirm`) 대신 JT 인앱 모달 적용.
  - 저장 실패 시 JT UX writing 원칙(사과 금지, 원인 및 해결책 안내) 적용.

## 2. 세부 구현 단계
1. **가짜 데이터 제거**:
   - `pages/settings.jsx` 및 `pages/records.jsx`에서 `DEFAULT_DEPARTMENTS` 더미 데이터 주입 로직 삭제.
   - 데이터가 없을 때 깔끔한 빈 상태(0건) 렌더링.
2. **부서 CRUD 기능 완성**:
   - 부서 추가 시 중복 검사, 첫 부서 자동 기본 지정.
   - 기본 부서 변경(기본 지정 버튼) 기능.
   - 부서 삭제 시 인앱 확인 모달(`confirmModal`) 호출 후 안전하게 삭제.
3. **'촬영' 및 '기록' 화면과의 완전한 동기화**:
   - `STORAGE_DEPARTMENTS_KEY = 'jt-vial-departments'` 키로 통합.
   - '기록' 화면에서 등록된 부서가 없을 때 안내 및 링크 연결.
4. **검증**:
   - Next.js 정적 빌드 및 디자인 규칙 정적 검사.
