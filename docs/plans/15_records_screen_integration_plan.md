# 15. '기록' 화면 기능 구현 및 '촬영'·'설정' 연동 계획서

## 1. 개요 및 목적
- **목적**: '기록' 화면(`pages/records.jsx`)에서 하드코딩된 가짜 데이터(INITIAL_RECORDS)를 제거하고, '촬영' 화면(`pages/index.jsx`)에서 저장된 실제 검수 데이터(`jt-vial-records`) 및 '설정' 화면(`pages/settings.jsx`)의 담당 부서 목록(`jt-vial-departments`)과 유기적으로 연동합니다.
- **대상 사용자**: 체이스 (직장인/초보 개발자)
- **핵심 원칙**:
  - 화면 디자인/레이아웃 형태는 그대로 유지하며 기능만 연동.
  - 브라우저 기본 팝업(`alert`, `confirm`) 대신 JT 디자인 시스템 v5.0 기준의 인앱 모달(`Modal`) 적용.
  - 저장 실패 시 사용자 안내 문구(UX writing 원칙: 사과 없이 원인 및 해결 방법 안내) 제공.
  - 불필요한 토큰 낭비 및 광범위 수정 최소화.

## 2. 세부 구현 단계

### 2.1 저장소 키 및 인터페이스 표준화
- `STORAGE_RECORDS_KEY = 'jt-vial-records'`
- `STORAGE_DEPARTMENTS_KEY = 'jt-vial-departments'`
- 기본 부서 목록(최초 실행 시 폴백) 제공 및 설정 화면과 동기화.

### 2.2 '기록' 화면 (`pages/records.jsx`) 기능 연동
1. **가짜 데이터 제거 및 실제 데이터 로드**:
   - 컴포넌트 마운트 시 `localStorage`에서 기록 데이터 로드.
   - 기록이 없으면 자동으로 '빈 상태(0건)' 화면 렌더링.
2. **부서 목록 동기화**:
   - `localStorage`에서 '설정' 화면이 저장한 최신 부서 목록을 읽어와 드롭다운 옵션에 반영.
   - 기본 부서가 있으면 신규 항목에 기본 적용.
3. **인라인 수정 내역 영구 보존**:
   - 제품명, 차수, 담당 부서 변경 시 `localStorage`의 `jt-vial-records`에 즉시 반영.
   - 저장 실패(Quota, 권한 등) 시 앱 내 모달로 오류 안내.
4. **기록 삭제 기능 및 확인 모달**:
   - 기록 삭제 버튼 및 모달 확인창(브라우저 confirm 대체) 구현.
5. **상세 열람 연동**:
   - 캡 개수, 박스 개수, 박스당 수량, 총 개수 등 실제 검수 결과 상세 열람 표시.

### 2.3 '설정' 화면 (`pages/settings.jsx`) 데이터 영구 보존 연동
- 부서 추가, 삭제, 기본 부서 지정 시 `STORAGE_DEPARTMENTS_KEY`에 즉시 저장되도록 하여 '기록' 화면과의 연동 완성.
- 저장 실패 시 앱 내 모달 알림 및 에러 문구 표시.

### 2.4 안전성 검증
- Next.js 빌드(`npm run build`) 확인.
- 디자인 시스템 규칙 준수 확인(임의 hex/px 없음, alert/confirm 미사용).
