# 26. YOLO26 온디바이스 자동 추론 전면 연동 및 WASM/전처리 오류 수정 계획서

> 작성일: 2026-11-26

## 1. 개요 및 개선 목적
- **기존 문제**:
  - `best.onnx` 모델이 브라우저에서 실행될 때 `.wasm` 파일 경로를 찾지 못해 클래식 템플릿 매칭 엔진으로 폴백되거나, "아무 캡 정중앙을 클릭하면 해당 캡을 기준으로 전체 재계산합니다"라는 수동 클릭 안내가 노출되는 문제 발생.
  - 슬라이더 및 모드별(캡 모드 `class_id: 1`, 박스 모드 `class_id: 0`) 필터링 기준이 `score >= 0.35`로 연동되지 않음.
- **수정 목표**:
  1. Next.js + onnxruntime-web WASM 로딩 오류 완전 방지 (`public/ort-wasm/` 및 `public/` 루트에 WASM 바이너리 다중 배치).
  2. 수동 클릭 대기 배제: 사진 등록 즉시 `/best.onnx`로 온디바이스 자동 추론 실행 (수동 추가/제외 클릭 기능은 유지).
  3. 640x640 레터박스(Letterbox) 전처리 및 정확한 원본 좌표 역변환.
  4. `score >= 0.35` 기준 필터 및 모드별 클래스 분리(`vial_cap: 1`, `vial_box: 0`), 민감도 슬라이더(0.15 ~ 0.70) 실시간 연동.

## 2. 세부 구현 사항

### A. Next.js + onnxruntime-web WASM 로딩 안정화
- `public/ort-wasm/` 및 `public/` 경로에 WASM 파일 배치.
- `utils/yoloOnnx.js`에서 `ort.env.wasm.wasmPaths`를 정확히 매핑하여 오프라인 온디바이스 환경에서 WASM 파일 미검색 에러 원천 차단.

### B. 즉시 자동 추론 및 수동 추가/제외 유지
- 사진 업로드/촬영 즉시 `analyzeVialImageFile` 및 `analyzeBoxImageFile`에서 `/best.onnx`를 즉시 호출.
- "아무 캡 정중앙 클릭" 대기 안내 바를 제거하고, `● YOLO26 자동 탐지 완료 · 마커를 누르면 제외되고 빈 곳을 누르면 추가됩니다` 안내 표시.
- 캔버스 클릭 시 기존 마커 삭제 및 새 마커 추가 기능 유지.

### C. 640x640 레터박스 전처리 및 좌표 역변환
- 종횡비를 유지하며 640x640 회색 여백(`#727272`) 캔버스에 렌더링 후 $1 \times 3 \times 640 \times 640$ Float32 NCHW 텐서 생성 ($0 \sim 1$ 정규화).
- 출력 텐서 형태(`(1, 300, 6)` 및 `(1, 6, 8400)`)를 런타임에 판별하여 패딩과 스케일을 역계산, 원본 사진의 캡 중앙에 원형 마커 배치.

### D. score >= 0.35 기준 필터 및 슬라이더 연동
- 기본 신뢰도 임계값을 `0.35`로 설정.
- 캡 뚜껑 모드: `class_id === 1` (`vial_cap`)만 표시.
- 박스 모드: `class_id === 0` (`vial_box`)만 표시.
- 민감도 슬라이더 범위를 `15 ~ 70` ($0.15 \sim 0.70$)으로 설정하고 실시간 필터링 연동.
